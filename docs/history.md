# Kanade 專案功能演進史

這是一份根據 `Kanade` 專案 Git 歷史紀錄所整理的發展脈絡，記錄了從最初的硬體原型鷹架、矩陣掃描，一路演進到多種和弦觸發模式、LittleFS 動態和弦設定、Wi-Fi 網路熱點網頁配置、JIS 鍵位對應、單元/主機端模擬測試與 CI 自動化的完整歷程。

---

## 第一階段：硬體基礎與按鍵矩陣架構（Scaffold & Hardware Foundation）

* **ESP32-S3 原型鷹架**：初始化專案，建立基於 ESP32-S3 的原生 USB HID JIS 鍵盤專案骨架。
* **矩陣掃描升級**：從原本的「一鍵一 GPIO」改為 **6x6 二極體按鍵矩陣（Diode Key Matrix）**，有效節省晶片腳位並支援更多按鍵。
* **按鍵預對應與機器格式對應表**：為每一個實體按鍵賦予獨特的預對應 ID，並引入機器可讀的和弦對應表（Chord Map CSV）。
* **14 鍵核心合流**：確立 14 鍵和弦鍵盤（14-key chord board）的基礎架構。

---

## 第二階段：和弦核心引擎與核心輸入邏輯（Chord Engine & Send Modes）

* **動態載入與熱點編輯**：支援從 LittleFS 檔案系統載入儲存的和弦表，並允許透過手機 Wi-Fi 熱點即時編輯設定。
* **HID 佇列化（Queued Keystrokes）**：導入按鍵事件佇列，確保發送 USB 報告時不會中斷或卡住按鍵掃描。
* **瀏覽器和弦練習頁面**：建立可在一般電腦瀏覽器上模擬與練習和弦輸入的網頁介面。
* **靈活的和弦觸發模式（Timing & Release Modes）**：支援 **First-key-up（首鍵釋放即發送）** 等多種送出時機，讓使用者不必等所有按鍵同時放開就能提前觸發和弦，大幅提升速打體驗。
* **主機端模擬與核心抽離**：將和弦核心邏輯（Chord Logic）獨立抽離，以便在無需實際燒錄硬體的情況下直接於主機端執行單元測試。

---

## 第三階段：防錯、強固與安全性強化（Robustness & Security）

* **解析與防呆強化**：嚴格驗證食譜與和弦指令，防止因指令錯誤、佇列不完整或記憶體不足造成當機或覆寫損壞儲存的和弦表。
* **長按自動重複與鍵值分離**：支援方向鍵與退格鍵的 **Hold-repeat（長按連續重複）**；將字母鍵拆解為 `Press` 與 `Release` 事件，避免系統輪詢漏字。
* **CORS、API Token 與初始化防護**：
  - 支援 CORS 標頭與 OPTIONS 預檢請求，方便網頁設定與互動。
  - 首次開機自動產生 API Token，防止空白密碼導致設定 API 完全暴露。

---

## 第四階段：測試、自動化與架構重構（Testing, CI & Refactoring）

* **測試與 CI 自動化**：
  - 導入完整的主機端單元測試與端到端任務測試（如 `test_config_job`、`test_config_http` 等）。
  - 設定 GitHub Actions CI（`.github/workflows/ci.yml`），確保每次 Push 都會自動執行原生測試與韌體建置。
* **USB CDC 逾時優化**：將 USB CDC TX 逾時設為 0，避免日誌緩衝區滿載時卡住按鍵掃描。
* **核心共用與設定檔集中化**：
  - 將網頁練習頁面與韌體共用同一套 `chord_core` 邏輯與 API。
  - 將所有可調參數（時序、容量、腳位、熱點位址）集中至單一標頭檔進行統一管理。

---

## 第五階段：品牌定名與最終精進（Branding, Layout & Current State）

* **定名為 Kanade**：正式將鍵盤命名為 **Kanade**，讓裝置名稱、網頁介面與說明文件三者統一。
* **JIS 主機端佈局對應（Host Layout）**：
  - 導入 `host_layout`，透過主機端佈局統一轉發食譜，讓 JIS 鍵盤的特殊按鍵位置可以在不更動和弦對應表的情況下靈活對應。
* **熱點期間安全防護**：
  - 當 Wi-Fi 設定熱點啟動時，會自動暫停和弦鍵盤的背景運作，防止使用者在網頁設定時因誤觸實體按鍵而送出殘缺的和弦字元。
  - 確保自訂 HTTP 伺服器在處理請求時不會因慢速請求而延遲關閉熱點，兼顧反應速度與安全性。
