# Kanade 開發沿革

本文依 Git 提交紀錄整理專案的主要變化，按開發先後分段；它描述的是功能如何走到現在，不取代 README 的使用說明、[設計取捨](design-decisions.md)或[實機驗收清單](device-acceptance.md)。

## 1. 原型與輸入硬體定型（2026-11-10）

- 以 ESP32-S3 建立原生 USB HID 日文鍵盤原型（`ea7a301`）。
- 為實體鍵建立穩定的鍵 ID，並建立人編和弦 CSV、機器用對應表及編譯時檢查（`57c38ae`、`869a615`）。
- 確立 14 顆直連開關、低電位有效與按鍵消彈跳，和弦鍵位元順序成為韌體與測試共用的介面。

## 2. 和弦引擎、設定與練習工具（2026-11-10）

- 完成 14 鍵和弦引擎，依和弦表輸出字元組合／功能鍵／修飾鍵複合（`30a7297`、`3fbc263`）。
- 加入 USB HID 佇列，讓配方逐步送出而不必為整串文字停住掃描（`3eb3612`）。
- 加入 Wi-Fi SoftAP 設定頁與 LittleFS 活表；裝置可在手機上編輯和弦，存檔表取代出廠表（`e07ce09`、`b2f400d`）。
- 建立瀏覽器練習頁，並將和弦判斷抽成可在主機執行的 `chord_core`，可不接板測試輸入與送出時機（`8f915d6`、`e236696`）。
- 支援全放再送與首鍵放開即送，之後再補上彈回保護、長按重複及巢狀和弦處理（`11b344f`、`200fdc2`、`c9045ed`）。

## 3. JIS 配列與資料保護（2026-11-10）

- 將 ASCII 配方依 JIS 主機鍵盤位置轉換，並記錄主機需使用日文 106/109 鍵盤類型；USB 國碼不負責切換主機配列（`7a29368`、`c0d2219`、`4834346`）。
- 強化配方解析、和弦表驗證、佇列容量與 LittleFS 儲存流程，拒絕不完整或無法送出的設定，避免錯誤資料覆蓋有效表（`0417165`、`bf577e1`、`3c53694`）。
- 加入設定 API 的 CORS／OPTIONS 處理及首次開機 API token，避免空白設定讓 API 無保護（`e5afb59`、`0eeda01`）。
- 加入 raw 按鍵記錄、無規則比對診斷，以及按住方向鍵和 Backspace 時的韌體連發。

## 4. 共用核心、測試與設定期間的可靠性（2026-11-11）

- 讓韌體與 WebAssembly 練習頁共用和弦判斷及送出排程，降低兩邊行為分歧（`44ecb9e`、`07bb62e`）。
- 增加原生測試、共用配方測試向量、設定 HTTP／工作測試與裝置驗收清單；CI 在推送時執行測試和韌體建置（`d53f320`、`8fe2fd9`、`f5adbd5`）。
- 集中管理時序、容量、腳位與熱點位址，並記錄腳位和設計取捨。
- 熱點開啟時暫停和弦掃描與送鍵；設定伺服器以有限區塊處理請求，避免慢速連線妨礙關閉熱點（`d3c1520`、`e4d1fce`）。

## 5. 定名與 USB／BLE 輸出（2026-11-11）

- 專案、裝置與頁面統一使用名稱 Kanade（`16f4f5f`）。
- 把主機配列轉換抽成 `host_layout`，讓和弦表保留邏輯輸出，JIS 鍵位由輸出層處理（`040cac2`）。
- 新增 GPIO16 輸出選擇：開機時選 USB 或 BLE，避免同時送到兩個主機介面；選擇不寫入 NVS 或 LittleFS（`e3b00ae`、`1333e79`）。
- 為輸出切換與 GPIO15 熱點互動加入必要的重啟處理。BLE 未連線或主機未訂閱輸入報告時不補送按鍵；連線期間則等上一個通知完成才送下一個，避免慢速連線合併或遺失按鍵（`0752c40`、`822d777`）。

## 截至 2026-11-11 的專案狀態

- 硬體為 ESP32-S3-DevKitC-1 N16R8、14 顆一鍵一 GPIO 的輸入，以及 GPIO15 熱點開關、GPIO16 輸出選擇開關。
- 可輸出 USB HID 或 BLE HID；目前主機配列實作為 JIS。
- 和弦表有編譯進韌體的出廠版本，也可透過熱點編輯並存入 LittleFS；電腦瀏覽器可載入機器表練習。
- `pio test -e native` 驗證可在主機測試的邏輯；LittleFS、無線連線與實際 HID 輸出仍需依裝置驗收清單在實機確認。
