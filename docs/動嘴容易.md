# 動嘴容易，動腦另算

給 AI：只是想法，還不用做。

只給自己看。上面那句的意思是：不能只動嘴，也要動腦。

每一節先寫已經說出口的方向，再寫還沒答的問題。`答：` 空著的時候，這一節就還停在嘴上。不要照著開工，也不要把它抄進待辦或規格。

現況以這份寫下時的韌體為準。打法見 [打法](playing.md)，已決定要維持的見 [設計取捨](design-decisions.md)。

## 1. 自選配列時，到底在換什麼？

已經說的：現在只模擬成 JIS。希望也能換成 US 或 TW 之類。

US 的表已經寫在 `kLayoutUs`，還沒選成作用中。TW 那一題還沒答，不要做切換，也不要做 TW。

現況：作用中的配列只有 JIS（`kLayoutJis`）。配方先經過 `layout_apply`，再送 USB HID。ASCII 表是從 Arduino-ESP32 的 `KeyboardLayout_ja_JP` 抄進 `src/host_layout.cpp` 的，`Keyboard.begin` 用的就是這張。字母和數字的用途碼跟美式鍵盤相同。出廠表裡不同的是 `[`（0x30）和 `]`（0x31）。`Shift+8`／`Shift+9` 要變成 `（` `）`，以及 `Hankaku`、`Muhenkan`、`Henkan`、`Kana` 要被 Windows 當成半角/全角、無変換、変換、ひらがな，都靠主機把鍵盤類型設成 Kanade 的配列（目前只實作 JIS）。USB 國碼沒有設定，Windows 不會靠它切版面。重啟或重新列舉不會替主機把類型改成美式或繁體中文。JIS 的用途碼改寫和組合改寫都是空的，所以這一步現在不改配方；和弦表維持人寫的那樣。改配列只能由熱點做，尚未實作，不設硬體開關。另一張配列會是另一份 `HostLayout`，不是把 `begin()` 的參數寫死。`kLayoutUs` 的 ASCII 表抄自 `KeyboardLayout_en_US`，組合改寫只有 `Shift+8`→`Shift+9`、`Shift+9`→`Shift+0`。送鍵的三處仍傳 `kLayoutJis`，所以這張表還沒作用。

1. 和弦表裡的字保持不變，只改這些字對到哪一組鍵位？還是換配列時，表上該打出的字也要換？
   答：和弦表裡的字保持不變，只改這些字送出時對到的鍵位。

2. US、TW 各指哪一套？TW 是 Windows 繁體中文（注音或倉頡，鍵位常常仍是美式），還是另一套實體鍵位？清單裡要有哪些名字？
   答：US 是 Windows 把這顆鍵盤認成美式，後面是 Google 日文輸入法。表已寫好，作用中仍是 JIS。TW 還沒定。
