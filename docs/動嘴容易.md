# 動嘴容易，動腦另算

給 AI：只是想法，還不用做。

只給自己看。上面那句的意思是：不能只動嘴，也要動腦。

每一節先寫已經說出口的方向，再寫還沒答的問題。`答：` 空著的時候，這一節就還停在嘴上。不要照著開工，也不要把它抄進待辦或規格。

現況以這份寫下時的韌體為準。打法見 [打法](playing.md)，已決定要維持的見 [設計取捨](design-decisions.md)。

## 1. 自選配列時，到底在換什麼？

已經說的：現在只模擬成 JIS。希望也能換成 US 或 TW 之類。

這是已定的方向，還不是開工單。下面兩題沒答完之前，這一節整節不要做。

現況：作用中的配列只有 JIS（`kLayoutJis`）。配方先經過 `layout_apply`，再送 USB HID。ASCII 表是從 Arduino-ESP32 的 `KeyboardLayout_ja_JP` 抄進 `src/host_layout.cpp` 的，`Keyboard.begin` 用的就是這張。字母和數字的用途碼跟美式鍵盤相同。出廠表裡不同的是 `[`（0x30）和 `]`（0x31）。`Shift+8`／`Shift+9` 要變成 `（` `）`，以及 `Hankaku`、`Muhenkan`、`Henkan`、`Kana` 要被 Windows 當成半角/全角、無変換、変換、ひらがな，都靠主機把鍵盤類型設成 Kanade 的配列（目前只實作 JIS）。USB 國碼沒有設定，Windows 不會靠它切版面。重啟或重新列舉不會替主機把類型改成美式或繁體中文。JIS 的用途碼改寫和組合改寫都是空的，所以這一步現在不改配方；和弦表維持人寫的那樣。熱點頁不能改配列，也沒有指撥開關。另一張配列會是另一份 `HostLayout`，不是把 `begin()` 的參數寫死。

## 2. 「按下或放開來判定」指的是認定方式嗎？

已經說的：和弦組成現在用放開按鈕來判定。希望能切換，由按下或放開來判定。

## 3. 兩種送出時機，是要新做，還是把組合補測完？

已經說的：輸出時機現在是釋放判定。希望能調成全部放開才輸出，或第一顆放開就輸出。第 2 節若做了，要再確認切換設定有沒有問題。
